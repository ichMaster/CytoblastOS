## Findings for v0.4

The closing half of v0.4 asks for four lists. Three entries earned here, recorded
now rather than reconstructed later:

- **Call inventory (→ v1.2).** Five commands, all read-only, all documented in
  `readings.COMMANDS`: `df -k <path>`, `sysctl -n vm.loadavg`,
  `ps -Ao pid,pcpu,pmem,comm`, `sysctl -n kern.boottime`, `who`.
- **SDLC finding — `ps` CPU is not a sample.** `%CPU` from `ps` is averaged over
  each process's lifetime, so a process busy an hour ago still ranks high.
  Adequate for a prototype answer to "why is it slow"; a sampling collector is
  v2.1's job.
- **SDLC finding — substring keyword matching is unsafe across languages.** Two
  silent misroutes were caught by tests, not by review: `вільн` ("free") is a
  substring of `повільно` ("slowly"), and `free` is a substring of `freezing`.
  Fixed by matching at a word start; both have regression tests. Anything in v1.3
  that routes on text needs this lesson.
- **Limitation — the fallback is English only.** Answering "I don't know" in the
  user's language would cost a model call, which is not worth it. Worth revisiting
  when the orchestrator has cheap intent classification (v1.3).

Two questions v0.2 should settle before it is decomposed, both surfaced during
this phase:

- **The v0.2 DoD asks for a "temperature graph", but its tasks name CPU, memory,
  and disk.** On macOS temperature needs root (`powermetrics`) or third-party SMC
  tooling, which collides with v0's no-adapter rule. Either change the DoD
  example, accept a privileged fourth series, or treat "temperature" as a
  natural-language example the generator maps onto the nearest available series.
- **The chart widget.** Textual ships a `Sparkline`, which satisfies "renders and
  survives a restart" with no new dependency — the cheap choice for code that is
  disposable by declaration. A plotext-backed widget buys real axes at the cost of
  a dependency thrown away with the rest of v0.
