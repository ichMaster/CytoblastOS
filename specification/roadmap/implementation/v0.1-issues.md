# v0.1 — GitHub Issues

Issues for phase **v0.1 — Chat and system status** (version **v0 — Prototype:
monitoring, minimal search, and the generation SDLC**), derived from the
per-phase Tasks in [ROADMAP.md](../../ROADMAP.md) (§0.1) and the contracts in
[ARCHITECTURE.md](../../ARCHITECTURE.md) (§Trust modes, §Stack and repository
layout, §Configuration and secrets, §Error handling and resilience, §Testing and
CI). This file is scoped to a single phase; it is the first, so IDs start at
**CYTO-001…005**.

This phase stands up the repository, the toolchain, and one working path from a
typed question to a model-phrased answer about the machine — three direct macOS
readings behind it, no abstraction, no routing, no store. It is the first code in
the repository, so it also fixes the two things every later v0 phase inherits:
where the disposable prototype lives (`prototype/`, so the v0.4 freeze is
physical rather than a promise) and how the model is reached and mocked. The
invariants in VISION §Principles switch on in v1 — a prototype is exempt by
design, and no issue here builds an adapter, a gate, or a journal.

## v0.1 — Chat and system status

### CYTO-001 — Repository skeleton, toolchain, and configuration loading

**Description:**
The gate issue: the first code in the repository. Creates the `prototype/`
package that holds all of v0, the root `pyproject.toml` with the `uv` / `ruff` /
`pytest` toolchain, and `.env`-based configuration for the model key and model
id. Touches `prototype/cytoblast_proto/` and the repository root only.

**What needs to be done:**
- `prototype/cytoblast_proto/` package with `__init__.py`; tests in
  `prototype/tests/`. **All v0 code lives under `prototype/`** so the v0.4 freeze
  is a physical boundary — v1 creates `core/`, `adapters/`, `modules/` etc.
  beside it (ARCHITECTURE §Stack and repository layout) and copies nothing.
- Root `pyproject.toml`: project metadata, the `cytoblast_proto` package path,
  runtime deps (`anthropic`, `textual`, `python-dotenv`), dev deps (`ruff`,
  `pytest`, `pytest-asyncio`), and `ruff` + `pytest` configuration (test paths
  pointing at `prototype/tests/`).
- `config.py`: loads `.env` (never committed — ARCHITECTURE §Configuration and
  secrets) and exposes `ANTHROPIC_API_KEY` plus `CYTO_MODEL_READ`, whose default
  is the **cheap fast tier** because every v0.1 path is a read
  (ARCHITECTURE §Trust modes). Suggested default `claude-haiku-4-5`; it is a
  config value precisely so it can be swapped, and the hosting and cheap/strong
  routing rule is not formally decided until v1.5.
- A missing or empty `ANTHROPIC_API_KEY` fails with a clear, actionable message
  at startup, not with a traceback from inside the SDK.
- `.env.example` documenting both variables.
- CI workflow running `ruff check` and `pytest` on every push (ARCHITECTURE
  §Testing and CI: `main` stays green to merge).
- Update `CLAUDE.md` — it currently states there are no build/lint/test commands
  and asks for the real ones when the first code lands (v0.1). Record the
  `prototype/` layout decision and the Textual choice there too.
- Update [ARCHITECTURE.md](../../ARCHITECTURE.md) §Stack and repository layout
  with a `/prototype` line marked v0-only and disposable, so the layout in the
  spec matches the repository.

**Dependencies:** None

**Expected result:**
`uv run ruff check` and `uv run pytest` both run green on a fresh clone, and
configuration is read from `.env` through one module.

**Acceptance criteria:**
- [ ] `uv sync` installs cleanly; `ruff check` and `pytest` both succeed from a
      fresh clone with no source files beyond the skeleton.
- [ ] All prototype code is under `prototype/`; no package is created at the
      repository root.
- [ ] **Unit test:** config loads values from a temporary `.env`, falls back to
      the documented default model id when `CYTO_MODEL_READ` is unset, and raises
      a clear error when the API key is missing — no real key and no network in
      the test.
- [ ] `CLAUDE.md` carries the real build, lint, and test commands; ARCHITECTURE
      §Stack lists `/prototype` as v0-only.
- [ ] Ties to the phase DoD: the skeleton every later v0.1 issue builds on
      exists, and CI proves it.

### CYTO-002 — Model seam: one completion call, mocked in every test

**Description:**
The single place the prototype talks to a model: an Anthropic client wrapper
exposing one function that takes a system prompt plus a user message and returns
text. Small on purpose — v0 makes direct calls with no contracts
(ROADMAP §v0), and the real model seam with cheap/strong tier routing arrives in
v1.3. Touches `prototype/cytoblast_proto/model.py`.

**What needs to be done:**
- `model.py` with a `complete(system: str, user: str) -> str` function over the
  official `anthropic` Python SDK (`client.messages.create`), using the model id
  and key from `config.py`.
- Define the seam so tests can substitute a fake: inject the client (or a
  `Completer` protocol) rather than constructing it at import time. **Every test
  in this repository uses the fake — a real call is never made in CI**
  (ARCHITECTURE §Testing and CI).
- Set a sane `max_tokens` for short terminal answers and read the text out of
  `response.content` by checking `block.type == "text"` — never index
  `content[0]` blindly.
- Failure is a degraded result, not a crash: a network error, an auth error, or
  a rate limit returns a short readable message the chat can print, so the turn
  ends with an apology rather than a traceback (ARCHITECTURE §Error handling and
  resilience — a read failure degrades, never blocks).
- Record which model id was used, so the answer path can surface it if needed.

**Dependencies:** CYTO-001

**Expected result:**
One function turns a prompt into text, and every test in the repository can
replace it without touching the network.

**Acceptance criteria:**
- [ ] `complete()` returns the model's text for a normal response, driven by a
      fake client that returns a canned `Message`.
- [ ] **Unit test:** each SDK failure class the wrapper handles (auth, rate
      limit, connection) produces a readable degraded string rather than
      propagating an exception — **against mocks; no paid call**.
- [ ] **Unit test:** a response whose first content block is not text is read
      correctly rather than raising.
- [ ] No test, fixture, or CI step requires `ANTHROPIC_API_KEY` to be a real key.
- [ ] Ties to the phase DoD: the model half of "question → answer" exists and is
      testable offline.

### CYTO-003 — Three system readings with parsers for the empty and error cases

**Description:**
The machine half of the phase: free disk space, load average with the top
resource consumers, and uptime/basic health. Each reading runs a macOS command
directly and parses its output into a small structured result. Touches
`prototype/cytoblast_proto/readings.py`.

**What needs to be done:**
- Three readings, each returning a structured value (a dataclass or dict) plus
  the raw output the model will be given:
  - **free space** — capacity, used, available, percentage, per mounted volume of
    interest;
  - **load and top consumers** — load averages plus the top N processes by CPU
    and by memory (name, pid, percentage);
  - **uptime / basic health** — boot time, uptime, logged-in users.
- Parsers are pure functions over captured command output, kept separate from the
  subprocess call, so they can be tested against fixture strings.
- **Every parser handles the empty case and the error case**: no output, a
  truncated header, an unexpected column layout, and a non-zero exit each produce
  a result that says so — never an exception and never a silently wrong number
  (ARCHITECTURE §Error handling and resilience).
- Command execution is time-bounded, so a hung command cannot wedge a turn.
- Capture real output from this machine once and commit it as test fixtures.
- **Deliberately no adapter.** ROADMAP §v0 specifies direct calls, no
  abstraction; the OS boundary is laid down in v1.2 from the v0.4 call
  inventory. Do not introduce one here — but *do* keep a short note of every
  command invoked, since that inventory is a v0.4 deliverable.

**Dependencies:** CYTO-001

**Expected result:**
Three readings return structured, printable data about this machine, and each
parser survives the output it will eventually be handed on a bad day.

**Acceptance criteria:**
- [ ] Each of the three readings returns correct values when run against this
      machine.
- [ ] **Unit test:** each parser against a committed fixture of real command
      output, asserting the parsed fields.
- [ ] **Unit test:** each parser against empty output, malformed output, and a
      non-zero exit — the result reports the failure and the caller can render
      it; no exception escapes.
- [ ] **Unit test:** a command that exceeds its time bound is reported as a
      failed reading rather than blocking.
- [ ] The commands used are listed in the module (docstring or a constant) as the
      seed of the v0.4 call inventory.
- [ ] Ties to the phase DoD: the data behind "how much free space is left" and
      "why is it slow" is available and trustworthy.

### CYTO-004 — The turn: question → reading → answer in the user's language

**Description:**
The join: given a typed question, pick the relevant reading, run it, and hand the
raw result to the model with a system prompt that produces a short answer **in
the language the user wrote in**. This is the phase's DoD in one module. Touches
`prototype/cytoblast_proto/turn.py`.

**What needs to be done:**
- Reading selection from the question text. **Rule-based (keyword/pattern), not
  model-driven** — real routing belongs to the orchestrator in v1.3, and building
  a miniature one here is scope that gets thrown away twice.
- A system prompt that instructs: answer from the supplied reading only, answer in
  the user's language, be short and concrete, and say plainly when the reading
  failed.
- `answer(question: str) -> str`: select → read → compose prompt → `complete()` →
  return text.
- A degraded reading is passed to the model as such, so the answer explains what
  could not be read rather than inventing a number.
- An unrecognised question returns a direct, honest fallback naming what this
  prototype can answer — no model call needed.
- The two DoD questions are covered by selection rules: "how much free space is
  left" → free space; "why is it slow" → load and top consumers.

**Dependencies:** CYTO-002, CYTO-003

**Expected result:**
One function takes a question and returns an answer about this machine, with the
model doing the phrasing and the readings doing the knowing.

**Acceptance criteria:**
- [ ] **Unit test:** selection maps each phrasing family to the right reading,
      including at least one non-English phrasing per family, and unrecognised
      input to the fallback.
- [ ] **Unit test:** a failed reading reaches the prompt as a failure, and the
      fallback path makes **no** model call.
- [ ] **Integration test:** one full turn from question to answer against a
      **mocked model and stubbed readings** — asserting the reading's data
      reaches the prompt and the model's text is returned unchanged. No paid
      call, no real system mutation.
- [ ] Ties to the phase DoD: both "how much free space is left" and "why is it
      slow" produce useful answers through this function.

### CYTO-005 — Textual chat application with scrollable history and exit handling

**Description:**
The surface: a full-screen Textual app with a scrollable conversation log and an
input line, calling `answer()` per turn. Touches
`prototype/cytoblast_proto/app.py` plus its entry point. This is the only issue
that touches Textual — everything below it stays importable and testable without
a terminal.

**What needs to be done:**
- A Textual `App` with a scrollable log widget for the conversation and an input
  widget at the bottom; user turns and answers are visually distinguishable.
- History scrolls with keyboard and mouse and auto-scrolls to the newest message
  unless the user has scrolled up.
- The model call runs without freezing the UI (Textual worker / async), with a
  visible "thinking" indicator while a turn is in flight, and input disabled or
  queued until it returns.
- Exit handling: `Ctrl+C`, `Ctrl+D`, and a `/exit` command all quit cleanly and
  restore the terminal; an in-flight turn is cancelled rather than orphaned.
- A console entry point (`cytoblast-proto` or `python -m cytoblast_proto`) that
  starts the app, and a startup message naming the three things it can answer.
- A missing API key is reported in the UI (or before it starts) as a readable
  message, not a stack trace over a half-drawn screen.

**Dependencies:** CYTO-004

**Expected result:**
`uv run cytoblast-proto` opens a chat in the terminal that answers questions
about this machine and exits cleanly.

**Acceptance criteria:**
- [ ] **Integration test:** using Textual's `run_test()` pilot with a **mocked
      model and stubbed readings** — type a question, submit it, and assert both
      the question and the answer appear in the log widget. No paid call, no real
      system mutation.
- [ ] **Unit test:** `/exit` and the quit binding both terminate the app; a turn
      in flight is cancelled on quit.
- [ ] **Unit test:** an error returned from the turn is rendered as a message in
      the log rather than crashing the app.
- [ ] Manual check on macOS: history scrolls, the UI stays responsive while the
      model is answering, and `Ctrl+C` leaves the terminal usable.
- [ ] Ties to the phase DoD: the two questions are asked and answered **in the
      terminal**, which is what the phase closes on.

## v0.1 scope notes

**Total effort:** roughly 2–3 weeks (one M gate, two M, two S).
**Critical path:** CYTO-001 → CYTO-002 → CYTO-004 → CYTO-005.
**Phase DoD (ROADMAP §0.1):** "how much free space is left" and "why is it slow"
get useful answers in the terminal.
**Contracts pinned this phase:** **none.** v0 is explicitly contract-free — direct
calls, no abstraction (ROADMAP §v0), and its integration code is declared
disposable up front. The seams in ARCHITECTURE §Contracts are pinned from v1.1
onward. The only spec edit here is the `/prototype` line in ARCHITECTURE §Stack
and repository layout (CYTO-001), recording where the disposable code lives.
**Decisions taken in this phase:** the prototype lives in `prototype/` so the
v0.4 freeze is physical rather than an intention (ROADMAP §Open decisions,
"Prototype survival"); the chat surface is Textual; the model id is a config
value defaulting to the cheap fast tier, per ARCHITECTURE §Trust modes.
**No write paths.** The policy gate does not exist until v4 and no v0.1 issue
mutates the system — every reading is read-only, so no trace or restore-point
criteria apply. An issue in this phase that writes anything outside its own
output is a scope error.
**Mock note:** the model and the OS readings are **mocked** in tests — never a
paid call, never a real system mutation in CI. Destructive paths run against the
disposable VM outside CI (ARCHITECTURE §Testing and CI); this phase has none.
